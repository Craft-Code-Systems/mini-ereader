# Decision 0001: Use ESP32-S3-WROOM-1 as the MCU

**Status:**      Accepted
**Date:**        2026-09-05

## Context

A mini e-reader must render text to a small display and, to be useful,
fetch books over the network. That argues for an MCU with wireless, enough
RAM to hold a display framebuffer and decompress text, native USB for
programming without an extra bridge chip, and a large hobbyist/tooling
ecosystem. Candidates: ESP32-S3, RP2040, and nRF52840.

Constraints for v0.1: certified pre-made RF module (no custom RF layout),
solderable by hand or low-cost assembly, and driveable from Arduino /
ESP-IDF / MicroPython with existing E-Paper libraries.

## Decision

Use the **ESP32-S3-WROOM-1** module (N8R2 baseline: 8 MB flash, 2 MB
PSRAM; N16R8 as a drop-in upgrade).

## Considerations

**Pro:** Wi-Fi + BLE on-module and pre-certified; PSRAM comfortably holds
framebuffers and decompression buffers; native USB (USB-Serial-JTAG) means
no CP2102/CH340 bridge; huge library support including GxEPD2/epdiy for
E-Paper; cheap and widely stocked.

**Con:** Higher active/Wi-Fi-TX current than an nRF52 (peaks ~500 mA on TX),
which stresses the power path; module antenna keep-out constrains layout.

Rejected: **RP2040** — no wireless (would need a co-processor for sync),
which defeats "fetch books". **nRF52840** — excellent low power and native
USB, but BLE-only wireless is awkward for downloading books and its RAM is
tighter for framebuffers; revisit if the product pivots to ultra-low-power,
sideload-only.

## Consequences

- Power path must tolerate 500 mA bursts; bulk decoupling sized accordingly
  (see [Decision 0003](./0003-power-architecture.md)).
- Layout must honour the module antenna keep-out (module at board edge,
  no copper under antenna).
- Programming/reset design assumes native USB (see
  [Decision 0004](./0004-native-usb-programming.md)).
- Pin map in `DESIGN.md` avoids strapping pins and on-module flash/PSRAM
  pins (26–37).
